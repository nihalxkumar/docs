# Tools (Executable Functions)

Interactive functions that perform operations and return results. Tools can search, analyze security, check system state, and install packages.

## Search Tools

Tools for discovering packages and documentation across the Arch ecosystem.

### search_archwiki

Query Arch Wiki documentation with intelligent ranking.

**Parameters:**
- `query` (string): Search terms or keywords

**Features:**
- Ranked results by relevance
- Automatic keyword extraction
- Context-aware suggestions
- Multiple result snippets

**Example:**
```json
{
  "query": "systemd boot configuration"
}
```

**Returns:**
- List of matching Wiki pages
- Relevance scores
- Page excerpts
- Direct links

### search_aur

Search AUR packages with smart ranking algorithms.

**Parameters:**
- `query` (string): Package name or description keywords
- `sort_by` (optional): `relevance`, `votes`, `popularity`, `modified`

**Features:**
- Multi-factor ranking
- Vote count weighting
- Popularity metrics
- Last modified dates

**Example:**
```json
{
  "query": "terminal emulator",
  "sort_by": "popularity"
}
```

**Returns:**
- Matching AUR packages
- Vote counts
- Maintainer info
- Short descriptions

### get_official_package_info

Lookup official repository packages with hybrid local/remote search.

**Parameters:**
- `package` (string): Package name

**Features:**
- Local database priority
- Remote fallback
- Detailed metadata
- Dependency information

**Example:**
```json
{
  "package": "vim"
}
```

**Returns:**
- Package version and repository
- Dependencies and conflicts
- Installation size
- Description and homepage

## Installation Tools

Secure package installation with automated safety checks.

### install_package_secure

Install packages with comprehensive security validation.

**Parameters:**
- `package` (string): Package name to install
- `from_aur` (boolean): Whether package is from AUR
- `skip_security_check` (optional): Force skip checks (not recommended)

**Features:**
- Automatic PKGBUILD analysis
- Metadata risk evaluation
- Malicious pattern detection
- User confirmation prompts

**Security Checks:**
1. PKGBUILD safety analysis
2. Maintainer reputation check
3. Vote/popularity validation
4. Dependency verification

**Example (AUR package):**
```json
{
  "package": "yay",
  "from_aur": true
}
```

**Example (Official package):**
```json
{
  "package": "vim",
  "from_aur": false
}
```

**Returns:**
- Installation status
- Security check results
- Warning messages
- Installation logs

**Safety Features:**
- Blocks high-risk packages automatically
- Warns on medium-risk patterns
- Requires confirmation for AUR packages
- Provides detailed risk explanations

<Tip>
Always review security warnings before proceeding with AUR installations. The tool blocks known malicious patterns but cannot catch all threats.
</Tip>

## Security Tools

Comprehensive analysis tools for evaluating package safety.

### analyze_pkgbuild_safety

Deep analysis of PKGBUILD files for security risks.

**Parameters:**
- `package` (string): AUR package name

**Detection Capabilities:**
- Malicious commands (curl | bash, chmod 777)
- Obfuscation techniques (base64, eval)
- Cryptocurrency miners
- Network exfiltration
- Privilege escalation
- Suspicious dependencies

**Example:**
```json
{
  "package": "suspicious-package"
}
```

**Returns:**
- Risk level (low/medium/high/critical)
- Detected issues with line numbers
- Pattern explanations
- Recommendations

**Risk Levels:**
- **Critical**: Known malicious patterns, installation blocked
- **High**: Dangerous commands, strong warning
- **Medium**: Suspicious patterns, caution advised
- **Low**: Best practices violations, informational

### analyze_package_metadata_risk

Evaluate package trustworthiness based on metadata.

**Parameters:**
- `package` (string): AUR package name

**Analysis Factors:**
- Vote count (low votes = higher risk)
- Popularity metrics
- Maintainer reputation
- Package age
- Update frequency
- Orphan status

**Example:**
```json
{
  "package": "yay"
}
```

**Returns:**
- Overall risk score
- Individual metric scores
- Trust indicators
- Recommendation (install/caution/avoid)

**Trust Indicators:**
- High votes (>100) = trusted by community
- Regular updates = active maintenance
- Known maintainer = established reputation
- Old package = proven stability
- High popularity = widely used

## Package Removal Tools

Tools for safely removing packages from the system (Arch Linux only).

### remove_package

Remove a single package with various removal strategies.

**Parameters:**
- `package_name` (string): Name of the package to remove
- `remove_dependencies` (boolean, optional): Remove package and its dependencies (default: false)
- `force` (boolean, optional): Force removal ignoring dependencies (default: false)

**Features:**
- Basic removal (`pacman -R`)
- Removal with dependencies (`pacman -Rs`)
- Forced removal (`pacman -Rdd`)
- Shows disk space to be freed

**Example:**
```json
{
  "package_name": "firefox",
  "remove_dependencies": true
}
```

**Returns:**
- Removal status
- Packages removed
- Space freed

<Warning>
Use `force: true` with extreme caution as it can break system dependencies.
</Warning>

### remove_packages_batch

Remove multiple packages in a single transaction for efficiency.

**Parameters:**
- `package_names` (array): List of package names to remove
- `remove_dependencies` (boolean, optional): Remove packages and their dependencies

**Example:**
```json
{
  "package_names": ["firefox", "thunderbird", "gimp"],
  "remove_dependencies": false
}
```

**Returns:**
- Removal status for all packages
- Total space freed

## Orphan Management Tools

Manage orphaned packages (dependencies no longer required by any installed package).

### list_orphan_packages

List all orphaned packages with disk space usage information.

**Parameters:** None

**Features:**
- Uses `pacman -Qtdq`
- Shows total disk space usage
- Identifies candidates for removal

**Example:**
```json
{}
```

**Returns:**
- List of orphaned packages
- Individual package sizes
- Total space that can be freed

### remove_orphans

Remove all orphaned packages to reclaim disk space.

**Parameters:**
- `dry_run` (boolean, optional): Preview what would be removed without actually removing (default: true)
- `exclude` (array, optional): List of package names to exclude from removal

**Features:**
- Safe dry-run mode by default
- Package exclusion list
- Shows space to be freed
- Uses `pacman -Rns`

**Example:**
```json
{
  "dry_run": false,
  "exclude": ["lib32-gcc-libs"]
}
```

**Returns:**
- List of packages to be/were removed
- Space freed
- Operation status

## Package Ownership Tools

Tools for finding package-file relationships and investigating file origins.

### find_package_owner

Find which package owns a specific file on the system.

**Parameters:**
- `file_path` (string): Absolute path to the file

**Features:**
- Uses `pacman -Qo`
- Useful for troubleshooting
- Quick file-to-package mapping

**Example:**
```json
{
  "file_path": "/usr/bin/vim"
}
```

**Returns:**
- Package name
- Package version
- File path confirmation

### list_package_files

List all files owned by a package with optional filtering.

**Parameters:**
- `package_name` (string): Name of the package
- `filter_pattern` (string, optional): Regex pattern to filter files

**Features:**
- Uses `pacman -Ql`
- Regex pattern support
- Shows file types and locations

**Example:**
```json
{
  "package_name": "systemd",
  "filter_pattern": ".*\\.service$"
}
```

**Returns:**
- Complete file listing
- Filtered results if pattern provided

### search_package_files

Search for files across all packages in repositories.

**Parameters:**
- `filename_pattern` (string): File name or pattern to search for

**Features:**
- Uses `pacman -F`
- Searches all repository packages
- Requires package database sync (`pacman -Fy`)

**Example:**
```json
{
  "filename_pattern": "libssl.so"
}
```

**Returns:**
- List of packages containing the file
- File paths within each package

<Tip>
Run `sudo pacman -Fy` periodically to keep the file database up-to-date.
</Tip>

## Package Verification Tools

Verify integrity and authenticity of installed packages.

### verify_package_integrity

Check package files for modifications, corruption, or missing files.

**Parameters:**
- `package_name` (string): Name of the package to verify
- `thorough` (boolean, optional): Perform thorough check including file attributes (default: false)

**Features:**
- Basic check: `pacman -Qk`
- Thorough check: `pacman -Qkk`
- Detects modified files
- Finds missing files
- Checks file permissions

**Example:**
```json
{
  "package_name": "systemd",
  "thorough": true
}
```

**Returns:**
- List of modified files
- List of missing files
- Verification status
- Issue severity levels

## Install Reason Management Tools

Manage the install reason flag (explicit vs dependency) for packages.

### list_explicit_packages

List all packages explicitly installed by the user.

**Parameters:** None

**Features:**
- Uses `pacman -Qe`
- Useful for backup/restore workflows
- Shows user-installed packages only

**Example:**
```json
{}
```

**Returns:**
- List of explicitly installed packages
- Package versions
- Total count

<Tip>
Save this list to recreate your system setup on a new installation.
</Tip>

### mark_as_explicit

Mark a package as explicitly installed.

**Parameters:**
- `package_name` (string): Name of the package to mark

**Features:**
- Uses `pacman -D --asexplicit`
- Prevents package from being removed as orphan
- Useful for keeping dependencies you want

**Example:**
```json
{
  "package_name": "python-requests"
}
```

**Returns:**
- Operation status
- Updated install reason

### mark_as_dependency

Mark a package as a dependency.

**Parameters:**
- `package_name` (string): Name of the package to mark

**Features:**
- Uses `pacman -D --asdeps`
- Allows package to be removed as orphan if not required
- Useful for cleaning up explicitly installed dependencies

**Example:**
```json
{
  "package_name": "lib32-mesa"
}
```

**Returns:**
- Operation status
- Updated install reason

- Uptime

- Works on any Linux system

**Example:**
```json
{}
```

Check for failed systemd services.

**Parameters:** None

**Features:**

- Boot log entries
- Timestamps

## Tool Usage Examples

### Safe Installation Workflow
```
1. search_aur query="terminal emulator"
2. analyze_package_metadata_risk package="alacritty"
3. analyze_pkgbuild_safety package="alacritty"
4. install_package_secure package="alacritty" from_aur=true
```

### Package Research
```
1. search_archwiki query="package manager"
2. get_official_package_info package="pacman"
3. search_aur query="pacman helper"
```

### System Maintenance
```
1. check_updates_dry_run
2. get_official_package_info package="linux"
3. search_archwiki query="system update"
```
